# Vendored AMACS release artifacts

RFxchange consumes immutable AMACS release artifacts server-side and at build time. Participant browsers never fetch AMACS source data or GitHub content.

## Current release

- version: `0.5.0`
- release date: `2026-08-08`
- source repository: `AccelAnalysis/amacs`
- source commit: `da7879f2609271b067ae6d02875e9388a02c4fe5`
- artifact: `releases/0.5.0`

The artifact was produced by the official AMACS release builder:

```bash
git -C /path/to/amacs checkout --detach da7879f2609271b067ae6d02875e9388a02c4fe5
python /path/to/amacs/scripts/build_release.py \
  --output /tmp/amacs-release \
  --source-commit da7879f2609271b067ae6d02875e9388a02c4fe5
```

`scripts/ingest-amacs-release.mjs` verifies the manifest, source commit, complete file set, every SHA-256 checksum, schemas, record counts and references before generating RFxchange projections.

## Historical compatibility release

`releases/0.1.0` preserves the last AMACS 0.1.0 source state before the repository advanced to 0.2.0:

- release date: `2026-08-03`
- source commit: `7e4b6c88e91c2df6f1d596af1dec7701df0290d2`

RFxchange uses this projection only to preserve historical identifiers and label/definition snapshots. It is not a fallback current taxonomy and cannot silently remap historical records.

## Regeneration

From the RFxchange repository root:

```bash
npm run generate:amacs-0-5
npm run validate:amacs-0-5-reconciliation
```

The generation command is deterministic and writes only `src/generated/amacs/0.5.0`. CI compares every generated byte and checksum to the ingestion lock.
