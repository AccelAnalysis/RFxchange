# Brand Gate B6c — RFx lens

**Status: PLANNING AUTHORITY — NOT IMPLEMENTED. EXPRESSIONS BECOME ELIGIBLE ONLY FROM REAL WAVE 4 DOMAIN STATE.**

## 1. Objective

B6c extends the existing Exchange Light Spatial Workspace so real RFx opportunities and relationships can become geographically visible without creating a second shell, fake map, decorative dashboard or premature domain object.

## 2. Prerequisites

B6c consumes completed:

- B1 semantic foundation;
- B2 shared primitives;
- B3 cartographic convergence;
- B6a existing workspace foundation;
- Wave 3 permitted organization discovery where applicable.

Domain prerequisites are incremental:

| Expression | Earliest source authority |
| --- | --- |
| Opportunity beacon | real `ISS-019` published opportunity projection |
| Opportunity map/list/detail lens | Slice 4.4 publication + Slice 4.5 discovery |
| Potential-match explanation | Slice 4.6 bounded match record/projection |
| Pursuit relationship indication | real `RSP-004` pursuit state/event |
| Team relationship path | real accepted `TEM-003` participation/event |
| Response/submission path | real response/submission event and permitted visibility |

No expression is authorized merely because a prototype demonstrated it.

## 3. Spatial composition

- Preserve the B6a organization home and real Mapbox canvas.
- Use one top navigation and one search/filter system.
- Use responsive contextual edge/bottom sheets for RFx list/detail.
- Keep the geographic canvas primary when location matters.
- Preserve focal organization/opportunity visibility and existing camera controls.
- Use the B3 opportunity-beacon grammar and semantic tokens.
- Use gold/blue/green only according to approved meaning; submission/connection is not automatically an outcome.

## 4. Real-data requirements

Every RFx spatial object requires:

- authoritative source record ID;
- projection version;
- observation time;
- lifecycle/status allowed for the view;
- authorized geography/location precision;
- permission/publication scope;
- current server-side revalidation.

Browser/local state may preserve selected object/panel/viewport intent only. It cannot grant access, publish an opportunity or increase coordinate precision.

## 5. Map boundaries

Prohibited:

- fake/schematic SVG map in production;
- arbitrary CSS/DOM coordinates;
- invented organizations/opportunities/paths;
- static demo data represented as live;
- opportunity beacons before publication;
- paths drawn merely because a user clicked a button;
- private exact address reconstruction from locality-only projection;
- a second RFx-specific map shell.

Required:

- existing Mapbox renderer-owned coordinates;
- authoritative Census/TIGER/locality/organization location contracts;
- map/list/detail equivalent;
- keyboard/screen-reader structured alternative;
- truthful loading/empty/error/permission/expired states;
- reduced-motion/transparency acceptance.

## 6. Participant language

Use:

- Opportunity
- RFx
- Potential match
- Issuer
- Responses due
- Performance location
- Find a teammate
- Prepare response

Avoid ordinary participant language such as:

- projection;
- source record;
- observation time;
- controlled Exchange;
- synthetic object;
- canonical map layer.

Those concepts remain implementation/admin/provenance details.

## 7. No design regression

B6c must preserve the approved version-2 RFx hierarchy when it opens operational RFx surfaces:

- gold eyebrow + decisive title;
- restrained containers;
- continuous rows/tables;
- prominent connected lifecycle;
- shared responsive sheets;
- no permanent RFx left rail;
- no dashboard-card proliferation.

## 8. Acceptance

B6c is complete only when real configured-browser acceptance proves:

- authorized published RFxs render at correct permitted geography;
- unpublished/restricted/cancelled objects fail closed;
- map/list/detail synchronize;
- focal objects remain visible across viewports/modes;
- stale browser state cannot expose withdrawn/restricted objects;
- no synthetic runtime object or fake map exists;
- relationship paths correspond to real audited events;
- public/participant precision boundaries are preserved;
- the existing organization-home experience remains usable.
