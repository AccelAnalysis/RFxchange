# RFxchange Brand Experience Acceptance Matrix

**Status: PLANNING AUTHORITY — DOES NOT COMPLETE FEATURE IDS OR REPLACE DOMAIN-SPECIFIC ACCEPTANCE**

## 1. Purpose

A surface is not premium because it uses the RFxchange palette. It must be coherent, useful, trustworthy, accessible, performant, and truthful to authoritative state.

This matrix supplements, but never weakens:

- security and authorization acceptance;
- lifecycle acceptance;
- geography and marker acceptance;
- organization authority and privacy acceptance;
- RFx, referral, provider, credibility, commercial, and administrative acceptance;
- configured-browser acceptance;
- tracker Feature-ID evidence.

Every new or materially changed participant-facing feature should identify the applicable rows below.

## 2. Universal surface matrix

| Area | Required acceptance |
| --- | --- |
| Brand architecture | Product is named consistently; category descriptor and Accel Analysis endorsement are used only in governed contexts; no competing product identity is introduced. |
| Visual hierarchy | One focal task is clear; typography and spacing establish hierarchy before borders/cards; gold is restrained and semantic. |
| Semantic color | Gold means focus/connection, blue means intelligence/opportunity, green means appropriate positive outcome; color is never the only signal. |
| Typography | Sentence case, readable interface sizes, tabular numerals where useful, no thin type over variable imagery/maps, system-safe fallback works. |
| Real evidence | No invented organizations, opportunities, maps, statistics, outcomes, testimonials, provider availability, or live dashboards are represented as real. |
| Synthetic content | Tutorial/conceptual content is visibly labeled, isolated from live records, deterministic, and excluded from analytics/credibility. |
| State authority | UI reflects server/domain authority; optimistic state cannot grant access, activation, OPEN, qualification, credibility, award, or outcome. |
| Loading | Layout remains stable; operation is named when material; no false percentage; long operations explain status. |
| Empty | Actual condition is stated; one to three useful next actions; low density is not disguised; no blank unfinished-looking dashboard. |
| Success | Success is proportional and timestamped/provenance-aware where relevant; routine actions are not over-celebrated. |
| Error | Work preservation is explicit; narrow cause is stated safely; recovery action is available; generic “Something went wrong” is avoided. |
| Permission | Denial explains the relevant organization/role boundary without exposing protected data; no hidden bypass through URL or mode. |
| Expired/stale | Expired context, invitation, token, deadline, or state produces explicit recovery; stale browser state is not trusted. |
| Destructive | Consequence is stated; confirmation is appropriate; audit/retention rules remain intact. |
| Autosave | Saving, saved, failed, offline/local-only, and conflict states are distinct and truthful. |
| Responsive | Desktop, intermediate, and mobile layouts preserve the focal task and avoid horizontal overflow; touch targets meet requirements. |
| Accessibility | Keyboard, visible focus, labels, error association, screen-reader status, zoom/reflow, contrast, reduced motion, and non-color cues pass. |
| Performance | First interaction remains responsive; visual effects do not block content; representative data density remains usable. |
| Recovery | Refresh, sign-out/sign-in, interrupted onboarding, network loss, and route return preserve or truthfully restore state. |
| Analytics | Events describe actual user/domain activity; synthetic tutorial events are separated; no visual-only activity is counted as outcome. |
| Commercial separation | Paid, Founding, sponsored, or membership status does not resemble credibility, qualification, ranking, or outcome. |
| Provenance | Seeded, claimed, provider-verified, platform-observed, self-reported, counterparty-confirmed, and independently verified states remain distinguishable where relevant. |

## 3. Marketing/public surface matrix

| Area | Required acceptance |
| --- | --- |
| Hero | Full-bleed real media or approved product evidence; concise overlay; readable gradient; no boxed-dashboard feel. |
| Claims | Implemented capabilities only; causal claims are measured; outcomes and economic impact are not guaranteed. |
| Imagery | Rights and provenance are documented; no fake interface compositing; no invented testimonials/statistics. |
| CTA | `Explore The RFxchange` and `Sign in` or current approved equivalents route correctly and remain keyboard accessible. |
| Navigation | Public visitors cannot reach protected workspace functionality through navigation or URL. |
| Bottom matter | Policy, company, support, accessibility, and related links open dedicated routes; no fake anchors or dead links. |
| Media performance | Appropriate formats, responsive sources, lazy loading below fold, no autoplay audio, reduced-motion treatment, acceptable LCP/CLS. |
| Product evidence | Screenshots/video reflect actual current product or are explicitly labeled concept/tutorial; sensitive data is removed. |

## 4. Onboarding and activation matrix

| Stage | Required acceptance |
| --- | --- |
| Account | State survives policy review and verification flow; duplicate questions are avoided; sign-in/resume paths are clear. |
| Policy | Actual policy routes open separately without losing activation state; current acknowledgments are authoritative. |
| Geography | Accessible typeahead; authoritative locality; surrounding geography subdued; no hard-coded locality. |
| Organization resolution | Seeded vs claimed data is clear; duplicate/candidate states are understandable; authority cannot be inferred from selection. |
| Location | Address validation and geocoding are truthful; privacy-safe projection remains authoritative; errors preserve entered information. |
| Essential profile | Previously collected information is reused; optional data does not gate activation unless explicitly canonical; no customer-facing internal terms. |
| Marker | Real marker remains visibly anchored at the protected camera target in default 3D, 2D, Fit home, and after camera interaction. |
| Activation motion | Motion is internal to marker visual child; anchor does not drift; one pulse only; reduced-motion equivalent works. |
| Activation copy | `Your business is now on The RFxchange.` or locality-specific approved copy; no verification/qualification implication. |
| Next action | One clear next action; no wall of enrichment tasks at the success moment. |
| Sound | No sound unless authoritative activation succeeds and sound is enabled; visible equivalent is complete. |
| Resume | Refresh, sign-out/in, and interrupted flow return to the exact legitimate remediation/current stage. |

## 5. Spatial workspace matrix

| Area | Required acceptance |
| --- | --- |
| Canvas | Map fills the spatial viewport beneath one participant navigation; no ordinary page margins or decorative map card. |
| Focal target | Persistent desktop panel stops before protected horizontal center; mobile sheet stops before protected vertical center where required. |
| Organization node | Proprietary shape, anchored coordinate, mode-aware core, no generic white outline, keyboard-addressable. |
| Opportunity beacon | Distinct Signal Blue directional object; match does not imply qualification; false point geography is prohibited. |
| Locality field | Authoritative boundary, clear focus, surrounding context dimmed rather than erased, attribution visible. |
| Service field | Territory differs from office location; unknown coverage is not inferred; overlap remains legible. |
| Paths | Real or clearly synthetic relationship only; gold while active/explained; static after movement; green only for appropriate outcomes. |
| Layer hierarchy | Progressive detail by zoom/task; selected objects remain above supporting context; labels do not overwhelm. |
| Controls | Keyboard and touch accessible; visible focus; orbit, 2D/3D, fit, zoom, search, and filter controls do not obscure focal content. |
| Map/list parity | Structured list alternative reflects current filters/selections and supports non-spatial discovery. |
| Reduced motion | Orbit off; immediate boundary/path/marker state; no loss of information. |
| Performance | Representative markers/fields/paths remain interactive; hidden animation stops; map does not lock during panel changes. |

## 6. Operational workspace matrix

| Area | Required acceptance |
| --- | --- |
| Canvas | Warm Ivory/light default; geography may remain contextual but does not force a map-first workflow. |
| Forms | Clear labels, help, validation, required/optional distinction, stable controls, preserved values. |
| Dense data | Opaque readable surfaces; tabular numerals; sortable/filterable behavior accessible; glass not used behind long tables. |
| Workflow status | Current stage, responsible party, deadline, and next action are visible where domain supports them. |
| Drafts | Save state and version are clear; stale/conflict handling exists; no silent overwrite. |
| Submission | Review, acknowledgments, authoritative receipt/timestamp, and external-system boundary are explicit. |

## 7. Motion matrix

| Area | Required acceptance |
| --- | --- |
| Timing | Micro 120–180ms; panel 220–320ms; spatial 600–1,200ms; milestone about 2–4s unless a documented exception. |
| Easing | Longer movement uses smooth acceleration/deceleration; no linear abrupt camera motion; no bounce/elastic behavior. |
| Meaning | Motion explains state/continuity; it does not fabricate activity. |
| Interruption | Latest participant intent wins; camera/panel motion can be interrupted; navigation is not blocked. |
| Reduced motion | Equivalent final state and status; orbit disabled; no large travel or repeated pulses. |
| Focus | Focus moves predictably with drawers/modals and returns on close; animation does not hide focus. |
| Performance | Compositor-friendly where possible; no layout thrash; mobile and dense map remain responsive. |

## 8. Sonic/haptic matrix

| Area | Required acceptance |
| --- | --- |
| Authority | Sound/haptic fires after confirmed domain event, not before mutation success. |
| Controls | Master and category controls exist where implemented; preference persists; quiet hours and duplicates are handled. |
| Accessibility | Complete visual/screen-reader equivalent; disabling sound/haptic loses no meaning or function. |
| Restraint | No page-load, hover, typing, filtering, ordinary navigation, or every-notification sound. |
| Assets | Rights, provenance, version, loudness, duration, and semantic assignment documented. |
| Autoplay | No public marketing autoplay audio; browser policies respected. |
| Replay | Idempotency prevents repeated milestone sound; background tab behavior is safe. |

## 9. Viewing-mode matrix

| Mode | Required acceptance |
| --- | --- |
| Exchange Light | Warm Ivory/light default; semantic contrast; map and operational surfaces complete. |
| Intelligence Dark | Graphite/charcoal, not neon; semantic colors unchanged; charts/maps/tables/focus pass independent contrast review. |
| Presentation | Safe projection; private fields hidden; controls minimized; larger labels; provenance/caveats visible; real or labeled synthetic evidence only. |
| High Contrast | Forced-colors compatibility where possible; no translucent dense surfaces; non-color differentiation. |
| Persistence | No theme flash that obscures content; fallback remains usable; preference cannot block auth/recovery. |

## 10. Messaging matrix

| Area | Required acceptance |
| --- | --- |
| Voice | Direct, calm, human, specific, evidence-aware, next-action oriented. |
| Pattern | What happened, why it matters, what to do next. |
| Match | Potential fit is separated from qualification, endorsement, eligibility, profitability, and selection. |

## 12. Configured-browser matrix

At minimum, configured-browser acceptance should cover representative cases across:

- desktop primary viewport;
- intermediate/narrow desktop or tablet viewport;
- mobile viewport;
- Exchange Light;
- Intelligence Dark when implemented;
- reduced motion;
- orbit enabled/disabled;
- keyboard-only path;
- screen-reader semantics inspection;
- no-public-website and available-website activation cases;
- direct and acquisition-context registration;
- synthetic orientation isolation;
- first-value selection and OPEN remediation;
- offline/interrupted save where supported;
- external-submission boundary where applicable;
- presentation-safe projection when implemented.

## 13. Completion rule

A branding or UX PR may not claim “premium experience complete” unless:

- applicable matrix rows are named in the PR;
- automated tests enforce reusable contracts;
- configured-browser evidence covers the material paths;
- domain/security/lifecycle tests remain green;
- no feature completion is inferred from visual simulation;
- tracker changes correspond to actual authorized Feature-ID evidence;
- known gaps are explicitly recorded rather than hidden by visual polish.
