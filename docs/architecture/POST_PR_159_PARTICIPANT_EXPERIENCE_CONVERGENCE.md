## Purpose and boundary

This gate reconciles the implemented participant shell and spatial workspaces with the already-approved Exchange interaction, brand, map, lifecycle, security and continuity authorities. It changes no Feature ID, tracker total, Wave status or Brand Gate status. It does not create an RFx route or record, implement Slice 4.1, begin a later Wave 4 slice, change Firebase App Hosting/build identity, or introduce Dark Appearance, Presentation Mode, sound or haptics.

The participant organization, geography and authorization projections remain server-authoritative. The client spatial context introduced by this gate is a non-authorizing continuity projection only. Every route and selected-object lookup continues to validate current session, membership, organization, lifecycle, geography and object visibility on the server.

## Implementation seams

The correction uses these bounded seams:

1. A participant-spatial-context contract and session-storage adapter in the participant application boundary. It contains presentation continuity only and cannot authorize a route, organization, geography or action.
2. A shared map-view contract consumed by participant and activation map components.
3. The persistent participant shell as the only warm-transition owner.
4. Existing participant route resolution plus orientation/first-value repositories as the server lifecycle resolver.
5. Existing network, resource-provider and referral projections for server-validated selected-organization actions; unavailable actions remain explicit.
6. The existing `/geography/canvas` canonical Intelligence seam for safe return navigation.

## Explicit deferrals

- No RFx Feature ID, route, aggregate, beacon, match, draft, response, fabricated activity or unavailable-lens workaround is introduced.
- Network discovery remains bounded by its existing page contract; no cursor token is invented.
- No independent organization-detail API or new database projection is introduced unless implementation proves the current bounded projection cannot meet the approved interaction without a security or performance regression.
- Activation/onboarding may retain `MapboxLocalityCanvas`; it is not a peer participant spatial runtime after convergence.
- Stabilization 2C remains incomplete and isolated to release engineering.
- Brand Gate B6b remains intentionally pending.
- Slice 4.1 and later Wave 4 implementation begin only after this correction PR is reviewed, merged and post-merge green, under the user's separate Wave 4 authorization.

## Completion evidence

### Implemented result

- All three permanent available participant lenses render the governed Exchange spatial scene and consume one scoped, versioned session context. Camera, actual view mode, selected organization, per-lens query/filter/result position, list scroll, panel state and safe return intent persist independently and never authorize a route or object.
- Initial-entry camera work is isolated from normal interaction. The implementation fixes the Mapbox default 60-degree pitch cap (`maxPitch: 85`) and prevents an initial pre-load camera event from being mistaken for a restored participant camera. Selection, drawer changes, filters and lens changes no longer reapply 3D.
- The configured compact-marker source clusters unselected external organizations at wide zoom. The selected organization is projected through a separate non-clustered source, so it remains a standing marker at every zoom. Compact/selected treatments use organization initials instead of the product `RF` glyph. Home and external selections share the selected-object seam; cluster/organization layer hits take precedence over an overlapping home marker so cluster expansion cannot silently reset selection.
- Warm participant route loaders and the page-like `ParticipantContentLoading` surface are removed. The current authorized workspace remains until commit; link-local pending state is nonanimated, announced and contains no spinner, dot, progress bar, heading, card or artificial delay.
- Lifecycle resolution loads lifecycle and membership first. Only a `controlled-platform` participant incurs the real orientation-stage read: incomplete orientation resolves to `/orientation`, completed orientation resolves to the authoritative `/first-value` workspace, and that workspace performs the full first-value/OPEN evaluation. An `open-platform` participant preserves the requested Exchange lens without blocking on unrelated orientation or first-value reads.
- Account is a 30px avatar identity inside a 44px circular hit target at desktop and mobile sizes. The menu, keyboard model, lazy server-authorized Administration resolution and fail-closed behavior remain intact.
- Organization actions are projected from self/external identity plus real provider state. Manage Profile is self-only; Resources is available for self or a real official provider; Referrals carries the selected organization in the URL as non-authorizing continuity state and revalidates it against the current authorized discovery projection, including its actual result page. A stale, restricted or malformed selection leaves the composer explicitly unselected and never substitutes another organization. Opportunities/RFx remains explicit, unavailable and non-routable. Intelligence resolves only the bounded visible-page provider statuses, fails the optional projection closed, and never waits on full Resource discovery or catalog hydration.
- A selected published Resource provider and an organization-attached referral counterparty both resolve their current authorized Network page before changing the shared spatial selection. Providers or counterparties outside the default 24-result page therefore cannot leave the detail, map marker, cross-lens links and persisted organization focused on different entities.
- Returning from Resources or Referrals carries the selected organization separately from the saved Intelligence result query. Intelligence revalidates the selected organization against Network authority and, when filters exclude it, projects that one authorized marker/detail alongside the unchanged filtered result list rather than silently resetting to home.
- The permanent-lens navigation prefers the scoped spatial Intelligence destination whenever that context exists; the legacy Intelligence URL is only a fallback when no scoped spatial context is active. Resources likewise carries an independently authorized organization focus in addition to optional provider-detail state, so selecting a non-provider marker cannot reload a different Network page.
- Cold same-session reloads hydrate the latest scoped camera before Mapbox applies its initial scene, rather than persisting the default camera over a stored view. Out-of-page provider and direct Referral recipient selections pass their exact server-authorized organization focus into the workspace, replacing stale organization state before map/detail/composer initialization.
- In Referrals, selecting a marker other than the active referral's counterparty clears the relationship selection, removes the referral URL state and makes the clicked organization the explicit composer recipient. The map, detail and composer therefore cannot describe different counterparties.
- Intelligence detail-open/detail-close overlay changes apply actual left/right Mapbox padding through a padding-only camera update. They do not replay the initial scene composition or reset the participant's settled center, zoom, pitch or bearing.
- Participant location language is natural (`Near {locality}` / `In {locality}`), and internal projection, coordinate-source, privacy-treatment, lifecycle and legacy-capability labels are absent from participant detail copy in all five governed locales.
