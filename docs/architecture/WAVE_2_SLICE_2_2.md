# Wave 2 Slice 2.2 — Geography Rendering

## Scope

This slice implements:

- `GEO-004` authoritative locality boundaries;
- `GEO-005` selected geography focus treatment;
- `GEO-006` muted surrounding geography context.

Organization markers, location capture, service areas and GIS administration remain later work.

## Authoritative boundary contract

Boundary geometry is a separate canonical geography concern rather than UI chrome or a field overloaded onto organization location.

`AuthoritativeBoundaryGeometry` preserves:

- canonical RFxchange `geographyId`;
- Polygon/MultiPolygon GeoJSON coordinates in EPSG:4326;
- exact U.S. Census authority, dataset, vintage and source `GEOID`;
- source layer and reproducible query URL;
- retrieval time, coordinate precision and server-side generalization tolerance;
- SHA-256 integrity evidence;
- calculated geographic bounds and vertex count.

The domain constructor rejects unclosed rings, invalid coordinates, unsupported geometry, non-HTTPS sources, invalid integrity values and provenance that does not match the Slice 2.1 `GeographyDefinition.boundary` contract.

## Current authoritative data

The initial rendering snapshot is generated by:

`scripts/fetch-tigerweb-locality-boundaries.mjs`

It queries the official U.S. Census TIGERweb `State_County/MapServer/1` Counties layer, whose current description is January 1, 2025 vintage, requests GeoJSON in EPSG:4326, and records a small server-side generalization offset for interactive rendering performance.

The committed snapshot contains Portsmouth, Norfolk, Suffolk and Chesapeake independent-city geometries. This is authoritative launch-region seed data, not Portsmouth-specific domain logic. Additional locality snapshots or a later boundary delivery adapter can implement the same repository port.

## Controlled-locality model

`ControlledLocalityMapService` consumes a persisted `PrimaryOperatingGeographySelection`, the canonical geography repository and an authoritative boundary repository. It does not accept browser viewport state as the selected-locality authority.

It:

1. reloads the selected canonical definition;
2. loads the authoritative selected boundary;
3. resolves each canonical adjacent geography and its boundary;
4. rejects missing boundaries and incompatible source/vintage mixtures;
5. derives the camera from canonical Slice 2.1 metadata;
6. emits a deterministic layer stack.

## Layer ordering and visual policy

The stack is:

```text
10 surrounding fill
20 selected fill
30 surrounding outline
40 selected high-contrast outline
50 selected gold accent outline
60 locality labels
```

Surrounding locality fills use a transparent gray treatment while their outlines remain visible. The selected locality uses full Growth Green color plus a dark contrast outline and RF Gold accent. All outline layers render after fill layers so overlays cannot hide the geographic boundary.

## Coordinate projection and interaction

The reusable projection module converts EPSG:4326 coordinates into the SVG view box. Boundary paths, locality labels and future coordinate-anchored objects use the same projection and camera viewport.

The accessible zoom control changes only the bounds-derived camera padding. It reprojects every geographic object from its source coordinates; no geographic feature is positioned with viewport CSS pixels. `vector-effect: non-scaling-stroke` keeps locality outlines legible across zoom levels.

## Accessibility and performance

- SVG exposes a title and description.
- Zoom buttons have explicit accessible names and disabled terminal states.
- The selected boundary uses a dark contrast outline beneath its gold accent.
- Locality meaning is not communicated by color alone: labels, outline weight and a text legend reinforce focus state.
- Geometry is pre-fetched and modestly generalized during ingestion rather than fetched or simplified on every render.
- Polygon holes use `evenodd` fill behavior.

## Validation

- `test/geography-rendering.test.mjs` proves provenance/integrity, non-box geometry, malformed-geometry rejection, deterministic layer order, multiple zoom levels, coordinate anchoring and accessibility/contrast contracts.
- `scripts/validate-geography-rendering.mjs` gates the authoritative snapshot, generator, domain, projection, component and architecture evidence.
- visual browser QA validates the controlled canvas at desktop/mobile sizes and exercises zoom interaction.

## Explicit non-scope

- organization marker activation (`GEO-011`);
- organization address/geocoding or public-location privacy;
- service-area rendering;
- organization resolution or claims;
- upload/approval/version-administration workflows for arbitrary GIS data;
- road, parcel, opportunity, organization or resource layers;
- a commitment to SVG as the permanent map provider. The provider-neutral geometry, camera and layer contracts can drive a later renderer.
