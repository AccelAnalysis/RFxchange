# RFxchange Market-Ready Baseline — “The Wall”

> **Successor authority:** The Stage 1–2 baseline below is preserved as provenance. For Stages 3–6, `MOBILE_EXCHANGE_STAGES_3_6_AUTHORITY.md` supersedes its permanent-lens and pre-Exchange payment sequence: the fourth lens is Capabilities, Referrals is cross-lens/Menu-based, legitimate free participation reaches value before an optional Founding offer, and payment never becomes a general Exchange-entry gate.

**Product-owner objective:** get the wall standing, get people into the Exchange, and get paying Founding Members.

This is the immediate go-to-market baseline. Work that does not materially serve this journey, or prevent a material security/privacy/tenant/payment/legal/truthfulness defect, must not displace it on the critical path.

## Baseline journey

A legitimate new business can, in production and without administrator intervention:

```text
Register
→ establish / claim / create its organization
→ complete required authority and location activation
→ enter the persistent Exchange Room
→ see its own organization and the real authorized market
→ see and select all four permanent Exchange lenses
→ understand the sixteen-function value architecture through four stable action labels per lens
→ use functions that are actually operational and authorized
→ see only the individual non-usable function controls in their gray/disabled state
→ reach the Founding Membership offer
→ complete live recurring payment through the governed production payment path
→ return to RFxchange
→ be recognized as a paying Founding Member on the correct organization/account authority
→ re-enter later with that paid state preserved
```

## Permanent value architecture

The four lenses are critical infrastructure because customers must be able to see what RFxchange is becoming even before every function is complete:

1. Opportunities/RFx
2. Resources
3. Intelligence
4. Referrals

A lens is never hidden or disabled because some of its functions are incomplete.

Each lens presents exactly four stable action positions. The action's normal label remains visible. If the function cannot currently be used, only that action control is rendered gray/disabled and non-actionable.

Do not add participant-facing `Unavailable`, `Coming soon`, `Not yet available`, or equivalent status text merely to explain a gray action.

## Critical path test

A proposed task belongs ahead of the Market-Ready Baseline only if at least one is true:

- it blocks legitimate registration/authentication;
- it blocks organization authority/activation;
- it blocks the participant from entering or truthfully seeing the real Exchange market;
- it blocks the four-lens / sixteen-function value architecture from being presented truthfully;
- it blocks the Founding Membership offer, live payment, membership reconciliation, or paid-state persistence;
- it creates a material security, privacy, tenancy, geography, payment, legal, accessibility, or truthfulness defect in that baseline journey.

Otherwise the work may continue in parallel but does not displace the market-ready journey.

## Already-built versus baseline verification

Registration, organization activation, the Exchange Room foundation, and substantial domain functionality already exist in the repository. The baseline does not authorize rebuilding those systems merely because they require production verification or bounded correction.

Prefer:

```text
inspect existing runtime
→ verify current behavior
→ correct only the material seam
```

rather than:

```text
rebuild an already-existing subsystem
```

## What baseline completion does not mean

Market-ready does not mean:

- all sixteen actions are active;
- all four lenses are feature-complete;
- Teaming is complete;
- messaging/notifications are complete;
- every Intelligence layer exists;
- all Resource Provider workflows are complete;
- every Referral workflow is complete;
- every RFx slice is independently Verified;
- Stabilization 2C is complete;
- all program certification debt is retired.

It means the Exchange can admit a legitimate business, show it a truthful living market and the complete four-lens value architecture, and convert it into a correctly recognized paying Founding Member.

## Operating rule after baseline

Once the Market-Ready Baseline is proven in production, keep the Exchange live and progressively light up additional functions in the fixed sixteen-action architecture.

The operating model is:

```text
keep the Room standing
→ preserve the four lenses
→ keep sixteen stable action positions
→ attach real domain handlers as they become operational
→ gray only the individual action until then
→ continuously increase customer value without closing the Exchange
```
