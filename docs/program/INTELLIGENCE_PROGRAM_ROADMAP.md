# Intelligence Program Roadmap

Intelligence is a permanent analytical lens, not a theme, appearance, separate privileged market, or synonym for Network. Network is the current organization-network view/domain concept inside Intelligence. This roadmap is independent of numbered-wave visibility and authorizes no runtime by itself.

## Current foundation

- `INTEL-LENS-001`: permanent lens structure is implemented but not independently verified.
- `INTEL-ORG-001`: permitted organization/capability discovery exists but is not independently verified as complete Intelligence experience.
- `INTEL-MARKET-001`: the current map/list/detail Network workspace exists but retains the shared focus-link acceptance gap.

## Track A — dependency-independent

May enter bounded planning/implementation packets after this authority merges, using only current authoritative data:

1. `INTEL-PROVENANCE-001` — inventory current first-party and approved external sources, permissions, coverage, vintage, caveats, suppression and update behavior.
2. `INTEL-LAYER-001` — define a typed configurable layer contract distinct from lens, appearance and workspace.
3. `INTEL-CONTROLS-001` — accessible analytical control and map/list/data presentation over accepted layers.
4. `INTEL-LOCATION-001` — bounded Location Intelligence using current authoritative geography and organization/capability data, once a specific slice authority is approved.
5. `INTEL-FIRSTPARTY-001` and `INTEL-PROPRIETARY-001` — only after source-specific contracts establish what data exists and what claims it supports.

No analytical layer may be created merely to fill the map. Sparse or unavailable data receives truthful coverage/empty state.

## Track B — RFx-dependent

`INTEL-RFX-001` may be designed against public/minimized RFx contracts, but runtime waits for independent assurance of its source features and a specific Intelligence slice authority. It must not expose issuer drafts, private fit/pursuit/response state, responder identity, qualification or fabricated demand.

## Track C — Resource-dependent

`INTEL-RESOURCE-001` waits for accepted Resources source contracts. It preserves provider approval, service territory versus office location, current eligibility/intake/availability and privacy meaning.

## Track D — Referral-dependent

`INTEL-REFERRAL-001` waits for accepted referral contracts. Only permitted, minimized relationship context may enter analysis; consent and private fields remain protected.

## Track E — Site/facility and outcomes

- `INTEL-SITE-001` requires an authoritative site/facility source, permissions, provenance and product-specific workflow. It must not turn RFxchange into a general CRE listing marketplace.
- `INTEL-OUTCOME-001` remains unavailable until authoritative outcome observations and evidence/verification distinctions exist.

## Initial packet

`WP-INTEL-ROADMAP-01` is an inventory/design-authority packet, not a production-layer packet. It establishes provenance, available authoritative fields, source update/failure behavior, privacy suppression, candidate dependency-independent layer(s), acceptance types and proposed bounded execution authority. It changes no Feature ID and fabricates no dataset.

## Exit criteria

Intelligence experience completion requires every `INTEL-*` requirement to be Verified or explicitly approved Deferred/N/A, followed by Lane 07 cross-lens acceptance. Explicit deferral does not count as implemented.
